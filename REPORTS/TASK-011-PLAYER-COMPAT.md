# TASK-011 §11 — Apple TV / Player 兼容性 reality check

日期：2026-10-06
结论口径：本轮**做到了结构验证 + 一份外部证据 + 一步人工验证**，
**没有**把「理论支持」写成「已验证」。

## 1. 最重要的一条结论（本轮实测发现）

> **播放器用 M3U 里的 `tvg-id` 去 XMLTV 里找 channel，字符串必须完全一致（含大小写）。
> 对不上就什么都拿不到 —— 这是「节目单空白」最常见的根因。**
>
> —— Apple TV IPTV EPG 配置指南（utgardtv.com，2026）

这句话不是规范，是本轮**生产实测验证过的**：

| 阶段 | M3U 的 tvg-id | XMLTV 的 channel id | 交集 |
|:--|:--|:--|--:|
| 初版（错误） | `CCTV1.cn`、`BeijingSatelliteTV.cn`（iptv-org 英文 id） | `CCTV1`、`湖南卫视`（fanmingming 中文 id） | **0 / 43** |
| 修正后 | `CCTV1`、`湖南卫视`（= EPG channel id） | 同左 | **41 / 43** |

> 修正后的 2 个未命中项 = `France24.fr`、`FujianStraitsTV.cn`，
> 均为**已知无 EPG 频道**（EPG 源里确实没有），**非缺陷**。
> 数字口径详见 §7。

初版如果上线，**整个节目单功能 100% 失效**，而这个缺陷在「检查 M3U 里
有没有 tvg-id」时完全看不出来 —— 这是本轮最有价值的一个发现。

已落地为两道 fail-closed：

1. `tools/build_channel_metadata.py` 生成时就用 `epg_channel_id`；
2. `liptv/channel_metadata.py` 加载器交叉校验，不一致直接报错
   （不能只靠生成脚本 —— 配置可能被手改）。

## 2. 玩家如何导入 M3U（外部证据，非猜测）

来源：utgardtv / iptvdb / nanoiptv 三份独立文档 + 本项目生产实测。

| 机制 | 支持情况 | 对我们的影响 |
|:--|:--|:--|
| M3U URL 导入 | 所有主流播放器（iPlayTV / IPTV Smarters / GSE / VLC）都支持 | ✅ 我们现有的 `/live.m3u` 形态没问题 |
| `#EXTINF` 的 `tvg-id` | **决定 EPG 能否匹配**，必须与 XMLTV channel id 完全一致 | ✅ 本轮已修正 |
| `tvg-logo` | 支持，但**必须是 HTTPS** —— 部分 tvOS 版本会拦截明文 HTTP 图片 | ⚠️ 我们的 logo 全部是 `https://`，符合 |
| `group-title` | 支持，用于频道分组 | ✅ 已在用 |
| M3U 头部的 `x-tvg-url` | **部分播放器自动读取，部分完全忽略** | ⚠️ 见§4 |
| 单独填 XMLTV URL | iPlayTV 等支持手动粘贴 XMLTV URL | ⚠️ 我们提供 `/epg.xml`，但**仅 200/503 等 HTTP 可达时**；APTV **不支持本地 XMLTV**（见 §6） |

### 关于 `x-tvg-url`

任务书 §10 提到可以在 `#EXTM3U` 头输出 `x-tvg-url`，但同时警告
「若 Apple TV 端无法访问服务器 localhost，则不要错误写 localhost URL」。

**本轮决策：不输出 `x-tvg-url`。** 理由：

1. 我们的服务只绑 `127.0.0.1`（这是 §47 红线，不改）；
2. Apple TV 访问不到上海服务器的 localhost —— 写了反而误导；
3. 外部证据明确说「部分播放器完全忽略这个标签」，
   依赖它等于把关键功能押在一个可选实现上。

**播放器需要手动填 XMLTV URL。** 这一步在 §6 的人工验证清单里。

## 3. logo 的可达性：判据来自玩家设备，不是服务器

生产实测：`live.fanmingming.cn` 在生产机被 DNS 污染到 Meta 网段
（`2a03:2880::`），curl 全部失败。

**但这不构成淘汰 logo 源的理由** —— logo URL 是写进 M3U 交给
**用户播放器设备**去请求的字符串，服务器的可达性与它无关。

这正是任务书 §4/§13 那条冻结认识的应用：
**不要把「服务器可达性」当成「播放环境可达性」的判据。**

同理，KORICE 在上海 probe 失败但家庭 VPN 能播 —— 同一个道理。

## 4. 动态赛事不继承 fixed EPG（§14 / §28）

实现：`_dynamic_channels()` 的 `tvg_id=None`（见 `liptv/publish.py`）。

理由：动态赛事是**临时 URL 的体育频道**，与 fixed 频道的节目单
没有任何关系。给它们套上 `CCTV1` 之类的 id 会让播放器把赛事节目
显示成 CCTV-1 的节目单 —— 这是**错误信息**，比没有更糟。

动态赛事仍然保留 TASK-008 的 collision 逻辑（同名加短标签），
`group-title` 独立分组。

## 5. tvg-id 字符集：为什么允许中文和 `+`

初版用 `[A-Za-z0-9._-]` 白名单，结果加载器**拒绝**了 `CCTV5+` 和 `湖南卫视`。

这不是「测试数据不规范」，而是真实约束：

- fanmingming / epg.pw / epg.112114 三个 feed 的 channel id 就是
  `CCTV5+`、`湖南卫视` 这类中文与带 `+` 的形式；
- 若拒绝它们，这些频道就**无法**满足「tvg-id == epg_channel_id」
  ⇒ 节目单匹配不上；
- 而 `CCTV-5+` 恰恰是任务书 §2A 点名「必须独立成条」的频道。

改为**排除法**：只禁止会在 M3U/XML 里产生歧义的字符
（引号、逗号、尖括号、反斜杠、斜杠、空白、控制字符），其余放行。
URL 里的转义由既有 `normalize_attr_value` 负责。

## 6. 需要 Owner 做的**一步**人工验证

自动测试与生产 smoke 只能证明「文件结构对」。下面这一步才能证明
「你家Apple TV 上真的能看到」：

> **原§6 第 2/3 步在 APTV 上不成立**（配置类型互斥）。以下是
> REVIEW-01 复验后按**具体播放器**重写的版本。

**先看清楚两个前提**（都是实测，不是推断）：

-服务**只绑 `127.0.0.1:8080`**，云安全组**只放行 22/TCP + ICMP**。
  ⇒ Apple TV 无论填 `127.0.0.1:8080` 还是服务器公网 IP 都**访问不到**。
  保持 localhost绑定是 §47 验收红线，**未解冻**。
- 所以**当前没有"URL 订阅"这条路**。M3U 与XMLTV 都只能是**文件**。

### 播放器能力对照（决定你走哪条路）

| 播放器 | 导入本地 M3U | 手填 EPG | 能否本地+EPG 兼具 |
|:--|:--:|:--:|:--|
| **APTV**（老李在用） | ✅ 本地配置 | ❌ 本地配置**无此字段** | **❌ 结构上不可能** |
| APTV | 只吃 URL（订阅配置） | ✅ 但**只吃 URL** | ❌ 仍需公网可达 |
| IPTV Smarters / GSE / VLC | ✅ | ✅ 多数支持本地 EPG | ✅ **可行** |

APTV 三个配置类型互斥：**能导本地 M3U 的那栏没有 EPG 输入框，有EPG 输入框
的那栏只收 URL**。Pro $3.99的「独立 EPG」同样要 URL，**买了也不解决**。
（免费版仅 1 条订阅配置 —— 频道数量不是问题，EPG 才是。）

### 因此，Owner 需要做的选择

**路线 A（零改动，推荐先试）**：换/用支持本地 EPG 的播放器
（IPTV Smarters / GSE / VLC 均可），把两个文件放到**同一文件夹**后导入。

1. 用 SFTP / WinSCP 以 `root` 登录服务器，拉两个文件到本机；
2. **两个文件必须放同一文件夹**（不少播放器靠相对路径找 EPG）；
3. 导入 `live.m3u`，再在播放器 EPG 字段**选同目录的 `epg.xml`**；
4. 点任一 CCTV 频道，确认节目单出现。

**路线 B（需 Reviewer 显式解冻 §27）**：把 8080 暴露到公网或接入内网通道
（Tailscale / NAS），用订阅配置 + EPG URL。**当前禁止** ——
§27 明令「不做公网暴露/DNS/TLS」，且验收第 47 条要求 localhost binding
unchanged。**解冻需大G 单独授权。**

**路线 C**：如实记录「Apple TV 实机未验证」，**不为凑一个"验证过"去破冻结**。

## 7. 诚实标注

### 四个数字的口径（别混用）

| 数字 | 含义 |
|--:|:--|
| **43** | M3U 里带 `tvg-id`/`tvg-logo` 的 **fixed 条目**数 |
| **42** | EPG XMLTV 的 `<channel>` 数（`restrict_to_metadata` 过滤后） |
| **41** | **43 个 tvg-id 中能在 EPG 里找到交集的个数** ⇒ 命中 41 / 未命中 2 |
| **2** | 未命中项：`France24.fr`、`FujianStraitsTV.cn`（均**已知无 EPG 频道**，非缺陷） |

⚠️ 所以「交集 41/41」的**分母是有EPG 的那批**，**不是 43**。
本节及§1 早期版本写作「41/41」容易被误读成「43 个频道全中」，已更正表述。
`#EXTINF` 总行数**会随赛事变动**（动态赛事每轮不同），不是固定值。
