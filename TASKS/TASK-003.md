## 目标与范围

首次形成可供播放器读取的**本地统一 M3U 文件**：将当前 SQLite 中已归一化、且已有合格历史探针记录的固定频道，与本轮即时抓取的动态体育赛事条目，在**单次显式命令**中合并、校验并安全发布到配置的 `out/live.m3u`。这次只做一次性组合/发布，不部署云服务、不做自动定时或真实测活；不能将“生成一个文件”描述成“24 小时可用的稳定订阅”。

### 1. 输入边界

- 固定频道：**复用** TASK-001 现有 `select_playlist`、基于历史 probe_result 的选线和现有 canonical/stream/provenance；本轮**不允许**绕过最低成功阈值，把从未探测的固定 stream 直接发布。用已有 mock probe_result 证明流程。
- 动态赛事：**复用** TASK-002 的 `preview_dynamic_source` / HTTP 限制 / M3U 结构校验；本轮只在命令显式启用动态合并时，拉取指定、已登记的动态源（初始示例 JSNZKPG）。继续与 `source_channel` / `canonical_channel` / `stream` 的长期身份与 7 日排序隔离；不落 SQLite 或把当次签名 URL 提交 Git。
- 仅从指定入口抓 M3U 文本；绝不请求/中转条目中的视频内容，不破解、不逆向、不延长令牌。
- 默认不自动联网：最短本地模拟演示可复现；JSNZKPG 真实网络获取仅可选手工 smoke。

### 2. 组合语义

- 固定频道按现有分类顺序输出，每个 canonical 最多一条合格线路；动态赛事独立 `体育赛事（实时）` 分组，保留比赛名和「[解说]/[原声]」区别，不把比分当作永久频道身份。不要凭名称臆断两场相同赛事。
- 同次动态来源的完全相同播放 URL + 原始显示名 + 原始分组可去掉**字节相同的重复条目**；不得跨固定频道与动态赛事盲目去重，也不得把「原声」与「解说」合并。
- 源含宣传入口、回放与实时赛事混杂：先给出**简单、配置化、可解释**的纳入规则，默认在动态板块只纳入明确被标识的赛事分组；过滤 `✈️TG频道` 等非赛事推广；`赛事回放` 单独可选、默认关闭。无法判断时优先不误删真正直播，记录过滤计数与理由；不要写复杂赛事识别。
- 输出为单个合法 `#EXTM3U` 头；每个条目 `#EXTINF` / URL 成对；生成内容本身必须通过解析与反向校验。
- 单次运行动态内容仅取本轮实际成功获取的条目，不从旧 `live.m3u` 或历史临时快照拼回动态线路。

### 3. 发布事务、安全与回滚

- 在任何写盘前完成固定选线、动态抓取（如果显式启用）、组合与完整校验。临时构建失败**不修改**当前 `live.m3u`，且不破坏 `live.previous.m3u`；写入使用同目录临时文件、原子替换与上一版备份，沿用 TASK-001 能复用的功能。
- **区别两种异常：** A. 输入/校验/本地 I/O 失败 → 整次发布拒绝、保留旧文件；B. 动态源 HTTP/解析失败 → 记录独立告警，默认 **fail-closed：不能沿用上一次动态签名 URL**；若本次有合格固定频道则明确降级只发布固定频道（允许操作者配置 `--require-dynamic` 使其整次拒绝）。有动态源但这次没有任何有效实时赛事，也按动态空集处理；不把旧动态节目带入新内容。
- 若动态失败、固定频道也为空：不得把已有文件误判为“永远有效”。明确输出 `DEGRADED_NO_PUBLISH`、错误码与风险告警。**本轮是单次静态文件**，在下一轮命令执行前无法自动过期；必须在报告中明确这一限制，避免承诺已解决无人值守的签名过期。可生成忽略于 Git 的 JSON 发布摘要/时间戳供后续任务监测，但不新增数据库业务表。
- 发布前设最小输出校验：条目与 URL 非空、固定 canonical 不重复、动态重复规则可解释、分类信息正确、输出头合法；不让全空结果在默认情况下覆盖已有正常列表。
- 生成失败及磁盘替换模拟异常要有可重复测试，证明当前与上一版文件保持不变；若现有 `m3u.write_m3u` 无法保证这些文件事务条件，允许对它作最小、兼容旧 API 的修复并新增回归测试。
- 持久日志/JSON 摘要**不得**包含完整签名 URL、动态整表或秘密值；包含本次 fixed/dynamic 数量、过滤数量、来源抓取结果、发布日期、输出 checksum、降级/拒绝原因。

### 4. CLI 与配置

- 新增一个清晰 CLI 入口，例如 `python -m liptv publish`；保留 TASK-001/002 原有命令和现有 `generate-m3u` 的兼容性，不暗中改变旧命令为联网命令。
- CLI 应支持：显式指定是否加入动态赛事、指定单个已登记动态源、动态失败时 `require` / 默认降级策略、指定输出路径、`--dry-run`（不改文件、仅输出脱敏校验摘要）。
- `config/config.example.toml` 提供禁用状态的 JSNZKPG 示例和赛事纳入规则、输出目录/发布策略的安全默认值。**不得**在导入配置后默认触发该公网源。
- 提供完整的“本地 mock 动态赛事源 + 已绑定固定频道 + 人工插入 mock probe_result → 统一 M3U 文件”的端到端演示脚本及 README 命令，全部离线可跑。

## 最低验收用例

1. 原 TASK-001/002 的 **151** 项测试零回归；新增跨模块及失败保护测试。
2. 离线 E2E：固定频道有有效 mock probe 历史 + 本轮动态成功 → 合并列表含两类条目、赛事[解说]/[原声]各自保留；固定优先且同频道只输出一条；过滤宣传与默认排除回放。
3. **失败与时间边界：** 上轮有动态节目，本轮动态源失败 → 新发布不能复制旧动态签名线路；可用固定频道则降级只发布固定；指定 `--require-dynamic` 则拒绝、原文件字节与备份不变；动态为空与全空结果均有明确输出与保护。
4. **文件完整性：** 从准备到成功发布前的异常（含写临时文件、备份、replace）注入测试；当前及 previous 不能发生半更新；同次重复发布行为可解释并记录 checksum；`--dry-run` 不触发任何最终文件写入。
5. **信息边界：** 动态播放签名 URL 只允许存在于本次内存/最终供播放器读取的本地运行文件中；不写 Git/明文日志/测试报告；保留 TASK-002 原有动态快照 Git 安全约束。
6. 两种来源的调用和出版顺序可追溯，异常有分类和退出码。离线测试/演示不得依赖 JSNZKPG 在线或实际转播流可播。
7. `git diff --check` 干净；报告提供真实测试命令、全部退出码、演示记录、边界说明、Git SHA；完整执行报告 `REPORTS/TASK-003-REPORT.md`。
