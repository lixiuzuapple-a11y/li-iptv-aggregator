## 阻断 QA-003A：真实 JSNZKPG 的赛事分组被默认过滤规则全部排除

项目引入 JSNZKPG 的主要目的，是让其**实时体育赛事**进入统一订阅，而不是只能通过改代码/手工搜集所有联赛名才能使用。目前 `publish.DEFAULT_DYNAMIC_FILTERS.include_groups` 与配置示例仅包含 `正在直播`、`即将开始`、`赛事回放`。但 JSNZKPG 发布的 `group-title` 是**各项联赛名称**，而“正在直播”是 M3U 内部注释分区标记，通常**不是各条目的 group-title**。

大G于 2026-10-01 通过 Windows WebCodex **只请求上游 M3U 文本**实测（未请求任何播放 URL）：HTTP 成功，**88 条**，分组统计：
```

VTB                3
国际友谊           4
欧俱杯             4
欧协杯             8
欧女杯             4
欧青U21外         10

非洲杯             2
赛事回放          50
```
其中**37 条非宣传、非回放的赛事线路**，现有默认 `classify_dynamic_entry` 的纳入数量：**0/88**。小W的 mock 样本使用 `group-title=正在直播`，未反映真实上游结构，导致所有 32 项新测试通过但目标源功能失效。

**必须修复：**
1. 不按“联赛分组名称只能是正在直播”来判断 JSNZKPG。给出适合其真实格式、简单配置化、可解释的纳入策略：默认排除宣传和回放，保留当期合法赛事联赛分组；如果利用 `# ===== 正在直播 =====` 等注释分区，应在本轮有可测、可复用的解析逻辑，而非长期硬编码当天联赛名单。
2. 用**脱敏的真实结构固定样本**（不含真实播放 URL/签名）追加离线永久回归：多个联赛分组、直播/回放分区、宣传、[解说]/[原声]，默认输出含赛事而不含回放/宣传；明确统计和提示。
3. 保持不请求底层视频、不持久保存动态签名以及固定频道与动态条目隔离。

## 阻断 QA-003B：多动态源有一个失败时，声明“仅固定”却发布了动态线路

`publish.build_composition()` 对每个动态来源分别累积成功条目。稍后 `publish()` 如发现 `dynamic_failed=True` 且固定频道非空，就将状态设为 `DEGRADED_FIXED_ONLY`，**却未移除其他成功来源纳入的动态内容**。这违反 TASK-003 的失败策略，也让状态、摘要和实际文件内容互相矛盾。

大G独立复现（真实 `publish()` 写入操作系统临时目录；固定选线和两项动态抓取结果通过 mock 控制，测试数据全为合成占位）：
```
两动态来源：good = 1 条当前赛事；bad = TIMEOUT。
STATUS DEGRADED_FIXED_ONLY FIXED 1 DYNAMIC 1 DYNAMIC_FILE True EXIT 0
```
`live.m3u` 实际包含动态线路，却显示“仅固定”。

**必须修复：** 与已冻结任务的默认失败语义保持一致：任一指定动态来源抓取失败，且有合格固定频道 → 默认真正只发布固定频道（舍弃本轮其他动态成功条目，计数和日志如实体现）；`--require-dynamic` → 拒绝且当前/备份不变；如果另有部分成功模式，必须明确另设配置和独立状态，不得把它冒充 `DEGRADED_FIXED_ONLY`，本轮不要求扩展该模式。追加真实输出 M3U 的离线回归：两个来源一成功一失败，检查状态、`dynamic_count=0`、实际文件**没有**任何动态线路，并验证单源失败与全成功均不回归。
